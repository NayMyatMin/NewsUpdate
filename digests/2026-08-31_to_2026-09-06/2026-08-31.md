### 6. [ContextLeak: Exfiltrating LLM Agent Context via Malicious Tools](https://arxiv.org/abs/2608.27800)
**Source:** ArXiv cs.CR | 2026-08-31 04:00 UTC | **Relevance:** 8.5/10

> This arXiv paper demonstrates ContextLeak, an attack where a malicious tool is engineered (using an RL-fine-tuned attack LLM) to (1) be selected by an LLM agent and (2) cause the agent to pass its runtime context (prompts, trajectory, tool list) as tool arguments, enabling exfiltration to attacker endpoints. The authors design reward functions to optimize tool name/description and evaluate robustness across shadow-user distributions, showing high effectiveness even with context mismatch.

**Why it matters:** Context exfiltration via malicious tools threatens agent confidentiality and highlights a concrete, deployable attack vector that Huawei must consider when designing tool registries, tool parameter handling, and provenance controls.

### 8. [ROPE: Routed Origin Policy Enforcement against Indirect Prompt Injection](https://arxiv.org/abs/2608.27496)
**Source:** ArXiv cs.CR | 2026-08-31 04:00 UTC | **Relevance:** 8.5/10

> ROPE introduces Routed Origin Policy Enforcement, a deterministic origin-tracing check that only allows values to reach sensitive tool parameters if they provably originate from authorized sources (user, user-named source, or authoritative records). The scheme provides formal guarantees against indirect prompt injection, holding attack success rates to ~1.6–2.6% while retaining 82–100% clean utility.

**Why it matters:** ROPE's provenance-based admission checks offer provable protections for agent tool execution and are directly applicable to Huawei's agent orchestration and secure tool-parameter flows.
